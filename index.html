Part 1 — Version (Release)

Odoo releases a new major version every year with new features, better UI and bug fixes

What is a Version?
  • One new major version is released every year — the number is a sequence, not the year (Odoo 20 = 2026)
  • New version = new features, better UI, better performance, bug fixes
  • Odoo 20 is the latest version (2026)
  • Each major version gets 3 years of standard support (bug and security fixes). After that: only paid extended support, on Odoo.sh or On-Premise only
  • Odoo Online also runs in-between SaaS versions (e.g. 19.1 – 19.4) — an Online client may be on "19.4"
⚠️
Important: Moving a company from one version to a newer one (e.g. Odoo 18 → Odoo 20) is an upgrade (via upgrade.odoo.com) — it is not automatic and must be tested first.

Odoo 20 — What's Different for Consultants

Changes since Odoo 17 that you will see in Odoo 20 — worth knowing before your first project

📦 Goods · Service · Combo Since 18
  • Goods replaces "Storable / Consumable" — tick Track Inventory to follow stock quantities
  • Combo bundles products sold as one line (e.g. restaurant menus)
  • Service products still drive Tasks, Projects and Timesheets
📊 Inventory valuation labels Since 19
  • Periodic (at closing) — the default — and Perpetual (at invoicing); older versions said Manual / Automated
  • Costing method Standard · Average (AVCO) · FIFO: a company default, overridable per product category
🔐 Access rights & record rules New in 20
  • Record rules are merged into access rights — one access right can now carry a filter
  • "Who can see what" is now one setting instead of two
  • Customisations built for older versions must be upgraded
🧾 Chart of accounts New in 20
  • Account codes are optional — an account can be set up with just a name
  • Parent accounts replace account groups for building the account hierarchy
💡
Trainer note: Always ask which version the client runs — screens, field names and valuation labels differ between releases, so confirm before you demo or configure.

Self Hosted — Full Control
🖥️
  • You install Odoo on your own system (laptop, VPS, AWS, company server)
  • You have full control over everything
  • Unlimited customization allowed
  • You handle backup, security & updates yourself

Community → Free (only server cost)
Enterprise → License fee + server cost

Cloud — No Installation
🌐
  • Odoo runs on Odoo's servers
  • You only use it in the browser
  • No installation required
  • Standard apps only — no custom or Apps Store modules
  • Odoo manages updates automatically
💰 Cost
Only Enterprise (Paid subscription)
Per user, per month/year. One App Free plan: one app at no cost.
Example: You login at company.odoo.com in your browser — this is Odoo Online (SaaS)
C. Odoo.sh (Cloud Platform)
Developer Cloud — Custom Modules
⚙️
  • Odoo's own cloud platform
  • You can install custom modules
  • GitHub based deployment
  • Odoo manages the server
  • Development, staging & production branches
💰 Cost
Only Enterprise (Paid)
Enterprise license + Odoo.sh subscription. No free option.
Flow: Developer Code → GitHub → Odoo.sh: Development → Staging → Production

Glossary — Terms You'll Hear Every Day

Part 1 — Sales, CRM, Purchase, Inventory and Manufacturing: short definitions

Sales & CRM
  • Lead vs Opportunity — a lead is a first, unqualified enquiry; an opportunity is a qualified deal moving through the pipeline (Leads must be switched on in CRM settings)
  • Quotation vs Sales Order — the same document — a "Quotation" until the customer confirms it, then a "Sales Order"
Manufacturing
  • BoM (Bill of Materials) — the recipe: components and quantities needed to make one product
  • Work Center — the machine, line or team where production steps are done, with its capacity and hourly cost
  • Work Order — one production step of a Manufacturing Order, done at a work center
Purchase & Inventory
  • RFQ vs Purchase Order — the same document — an "RFQ" while asking the vendor for a price, a "Purchase Order" once confirmed
  • Receipt / Delivery Order / Picking — stock transfers: goods coming in from a vendor / going out to a customer / collected from shelves before shipping (multi-step routes)
  • On-hand vs Forecasted quantity — on hand = physically in stock now; forecasted = on hand + incoming − outgoing
  • MTS vs MTO (Replenish on Order) — make-to-stock sells from existing stock; MTO creates a purchase or manufacturing order for each sales order
  • Reordering rule — min / max stock levels; when the forecast drops below the minimum, Odoo proposes a PO or MO

Glossary — Terms You'll Hear Every Day (2)

Part 2 — Accounting, projects and general implementation terms: short definitions

Accounting — Costs
  • COGS (Cost of Goods Sold) — what the products you sold cost you — an expense on the P&L
  • FIFO / AVCO / Standard cost — how a product's cost is calculated: first in first out, average cost, or a fixed cost you set
  • Perpetual vs Periodic valuation — stock value posted automatically when products are invoiced / billed, vs. entries proposed at period closing
  • 3-way matching — pay a vendor bill only when PO, receipt and bill quantities agree (Enterprise)
Accounting — Entries
  • Debit / Credit — the two sides of every journal entry; total debits always equal total credits
  • Reconciliation — matching items that belong together, e.g. a bank statement line with its payment — this makes an invoice "Paid"
  • Fiscal Position — rules that automatically swap taxes and accounts for certain customers or vendors (e.g. foreign or tax-exempt)
  • Lock date — date before which posted entries can no longer be changed — protects closed periods
Projects & General
  • Timesheet — time an employee logs on a project task — used for billing and cost
  • Milestone billing — invoicing a service when an agreed project milestone is reached
  • Fit-gap analysis — comparing client needs with standard Odoo; gaps go to configuration, Studio or development
  • SaaS / On-Premise — software run online by the vendor (Odoo Online) vs. installed on the client's own or rented server

Why Accounting Exists

The financial language every business speaks

FOUR KEY QUESTIONS ACCOUNTING ANSWERS
  • How much money do we have? — Checking bank & cash balances
  • How much do others owe us? — Receivables from customers
  • How much do we owe others? — Payables to vendors/suppliers
  • Are we profitable? — Income minus expenses = net profit (Profit & Loss)
FIVE ACCOUNTING ELEMENTS
  • Assets — What the business owns (cash, stock, equipment)
  • Liabilities — What the business owes (loans, bills to pay)
  • Equity — Owner's stake (Assets − Liabilities)
  • Income / Revenue — Money earned from sales or services
  • Expenses — Money spent to run the business
The accounting equation: Assets = Liabilities + Equity
Every transaction in Odoo maintains this balance automatically.

Assets
  • Cash & Bank
  • Accounts Receivable
  • Inventory / Stock

What the company owns

  • Bank Loans
  • Tax Payable

  • Deferred Revenue — paid by the customer before delivery
What the company owes
Equity

  • Current Year Profit/Loss
  • Owner's Investment
Owner's stake in the business

Income & Expenses

What drives profit and loss in Odoo

Income / Revenue
  • Sales Revenue — Product or service sold to customers
  • Service Income — Consulting, support, maintenance fees
  • Other Income — Interest earned, commission received
In Odoo: created when a Customer Invoice is posted
Expenses
  • Cost of Goods Sold — Cost of products sold
  • Salaries & Wages — Employee costs

In Odoo: created when a Vendor Bill is posted (for services and non-stocked purchases — stocked goods follow inventory valuation)
Net Profit = Income − Expenses   |   Shown in the Profit & Loss report in Odoo Accounting

Debit & Credit

The golden rule — every transaction has two sides

Account TypeDebit (Dr)Credit (Cr)
Assets (Cash, Bank, Receivable)Increases ↑Decreases ↓
Liabilities (Payables, Loans)Decreases ↓Increases ↑
Equity (Capital, Retained Earnings)Decreases ↓Increases ↑
Income / RevenueDecreases ↓Increases ↑
ExpensesIncreases ↑Decreases ↓
Memory Tip — DEALER:   Dividends, Expenses, Assets are Debit-normal  |  Liabilities, Equity, Revenue are Credit-normal
Dividends = profit paid out to the owners. It reduces equity, so it sits on the debit side.

Odoo Accounting Objects Explained

The six core objects you will work with every day in Odoo Accounting

📊
Account
A ledger bucket that collects related transactions, e.g. "Bank", "Sales Revenue". It has a name and a type; a code (e.g. 101000) is optional. Every transaction hits at least two accounts (Dr & Cr).
📔
Journal
A book that groups related entries. Journal types: Sales, Purchase, Cash, Bank, Credit Card, Miscellaneous. Each invoice posts to its journal.
📝
Journal Entry
The actual accounting record — a set of Dr/Cr lines that always balance to zero. Created automatically when you post an invoice, bill, or payment.
🧾
Invoice (Customer)
Bill you send to a customer for goods/services delivered. When posted: Dr Accounts Receivable, Cr Sales Revenue (and Cr Tax Payable for the tax).
📄
Vendor Bill
Bill received from a supplier. When posted: Dr Expense/Stock, Cr Accounts Payable. Matches the Purchase Order.
💳
Payment
Records money received (customer) or sent (vendor) and is linked to the open invoice/bill. It goes first to an "outstanding" account and reaches Bank when matched to the bank statement (see Invoice & Bill Flow).

Anglo-Saxon vs Continental Accounting

Two accounting traditions — they decide when a purchase becomes an expense

ANGLO-SAXON — usually perpetual
Used in: UK · USA · Canada · Australia · New Zealand
  • Stock stays an asset until sold, then becomes COGS — cost is booked with the sale
  • Usually paired with Perpetual valuation: stock accounts move with every bill and invoice
  • Income statement by function — COGS, Selling, Admin
Example: buy 10, sell 4 → COGS for the 4 sold is booked with the sale; 6 remain as an asset.
CONTINENTAL — usually periodic
Used in: Germany · France · Spain · Italy · Belgium
  • Purchases are booked as an expense when the vendor bill is posted
  • Usually paired with Periodic valuation: a period-end stock count adjusts the result
  • Income statement by nature — materials, wages, depreciation
  • Charts: PCG (France, prescribed by law) · SKR03 / SKR04 (Germany, DATEV standard charts)
Example: buy 10 → all 10 expensed at once; the period-end count credits back the 6 unsold units.
⚙️
In Odoo 20: the Anglo-Saxon setting comes with the country's chart of accounts (fiscal localization package) — on for the UK, Canada, Australia, New Zealand and the Generic chart used for the US; off for Germany, France, Spain and Italy. Periodic or Perpetual valuation is a separate, independent choice.

Which Standard Does Odoo Follow?

Odoo has no "IFRS" or "US GAAP" switch — the result comes from five configuration choices

1 Localization / chart of accounts
The country's fiscal localization package (the US uses the Generic chart) — sets accounts, taxes and statutory reports
2 Anglo-Saxon setting

Periodic or Perpetual — Accounting → Configuration → Settings → Inventory Valuation (company default; product categories can override)

Standard · AVCO · FIFO. Odoo has no LIFO — fits IFRS; a US GAAP company on LIFO needs adjustments outside standard costing

  • Which framework do the statutory books follow — local GAAP, IFRS or US GAAP?

Everything Is Connected

Actions in one module ripple across the entire system

Confirming a Sales Order triggers a Delivery Order in Inventory automatically.

Validating a vendor bill posts: Dr Expense/Stock, Cr Accounts Payable.

Inventory → Accounting

Logged timesheets feed into SO-based invoices via analytic accounts.

Common Mistakes in Odoo Implementations

What to watch out for as a consultant or trainee

CONFIGURATION MISTAKES
  • Installing modules the client doesn't need — creates confusion
  • Not setting up the Chart of Accounts before going live
  • Wrong costing method applied after stock moves exist
  • Not setting lock dates or checking taxes
  • Ignoring failed emails — check the email queue and the red envelope in the chatter (Odoo Online needs no SMTP setup)
PROCESS MISTAKES
  • Skipping the Draft → Confirm step on invoices/orders
  • Not reconciling bank statements regularly
  • Going live without training end users
  • Customizing before understanding standard flow
  • Not taking a database backup before major changes
  • Promising a feature without checking the edition (Community / Enterprise / Online)
